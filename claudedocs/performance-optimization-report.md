## 3. 번들 크기

### 빌드 결과

| 항목 | 크기/시간 | 비고 |
|------|----------|------|
| 전체 빌드 크기 | 43 MB | .next 폴더 전체 |
| 컴파일 시간 | 2.6초 | Turbopack 사용 |
| Static pages 생성 | 681.2ms | 11 workers |

### 라우팅
- `/` (Static): 정적 콘텐츠로 사전 렌더링
- `/_not-found` (Static): 404 페이지
- `/api/jasypt` (Dynamic): 서버 사이드 처리

### 분석
- 번들 크기는 11개 도구를 포함하여 43MB로 적절한 수준
- Turbopack 빌드 시스템으로 빠른 컴파일 시간 확보
- 코드 스플리팅으로 필요한 컴포넌트만 로드

## 5. 최적화 요인 분석

### 효율적인 아키텍처
1. **클라이언트 사이드 처리**
   - 모든 변환 작업이 브라우저에서 즉시 처리
   - 서버 왕복 시간 제로

2. **React 최적화**
   - useState로 상태 관리 (불필요한 리렌더링 최소화)
   - 컴포넌트 단위 분리로 효율적인 업데이트

3. **Next.js 16 (Turbopack)**
   - 빠른 빌드 및 Hot Module Replacement
   - 자동 코드 스플리팅

### 성능 영향 요소
- ✅ **Native JavaScript API 사용**: JSON.parse/stringify, RegExp, Date 등
- ✅ **최소한의 외부 라이브러리**: date-fns, js-yaml, cron-parser (필요한 것만)
- ✅ **효율적인 타입 시스템**: TypeScript로 런타임 오류 방지
- ✅ **Shadcn UI**: 가벼운 컴포넌트 라이브러리
